# Domain Validation with Puppeteer Fallback & LLM Context Generation

## Overview

When a domain is not directly accessible via HTTP, the system now automatically:
1. Tries HTTP with proper headers
2. Falls back to Puppeteer (handles JS rendering, anti-bot, cookies)
3. Falls back to Jina Reader API (final resort)
4. **If all methods fail**: Uses LLM to generate domain context based on domain name, location, keywords, and phrases

## How It Works

### Accessibility Check Flow

```
HTTP Request (5s timeout)
    ↓ (if fails/no content)
Puppeteer Browser (8s timeout)
    ↓ (if fails/no content)
Jina Reader API (5s timeout)
    ↓ (if all fail)
LLM Context Generation + Database Storage
```

### LLM Context Generation

When a domain cannot be accessed by any method, the system calls GPT-4o to generate realistic domain context including:

- **Business Description**: What the domain does
- **Industry**: Primary classification
- **Key Services**: Services offered
- **Target Audience**: Who it serves
- **Location Insights**: Market analysis for the location
- **Content Themes**: Suggested content topics
- **Suggested Keywords**: SEO keywords
- **Business Model**: Type of business

## API Usage

### POST `/api/domain-validation/validate-domain`

Request body:
```json
{
  "domain": "example.com",
  "location": "New York",
  "customKeywords": "SEO, digital marketing, web services",
  "intentPhrases": "How to improve SEO, digital marketing tips"
}
```

Response (Accessible Domain):
```json
{
  "success": true,
  "step": "Domain Validation",
  "status": "completed",
  "progress": 100,
  "message": "Domain is valid and accessible",
  "exists": false,
  "accessMethod": "http" | "puppeteer" | "jina"
}
```

Response (Inaccessible Domain - Uses LLM):
```json
{
  "success": true,
  "step": "Domain Validation",
  "status": "completed",
  "progress": 100,
  "message": "Domain created with AI-generated context (not directly accessible)",
  "domainId": 123,
  "exists": false,
  "aiGenerated": true,
  "note": "Domain details generated by AI based on location and keywords provided"
}
```

## Database Storage

### Domain Record Created With:
- `url`: Normalized domain URL
- `location`: Provided location
- `customKeywords`: Provided keywords
- `intentPhrases`: Provided phrases
- `locationContext`: AI-generated location analysis
- `contextJson`: Full LLM-generated context
- `isCompanyDomain`: Set to `true` for AI-generated
- `currentStep`: Set to `1` (started state)

### CrawlResult Record Created With:
- `pagesScanned`: 0 (no actual crawl)
- `extractedContext`: Summary from LLM
- `contextJson`: Full LLM-generated analysis
- `quality`: Default quality metrics
- `analyzedUrls`: Empty array
- `pageSnapshots`: Empty array

## Access Methods

The system returns which method successfully accessed the domain:

- **`http`**: Standard HTTP HEAD request (fastest)
- **`puppeteer`**: Browser automation (handles JS rendering)
- **`jina`**: Jina Reader API (anti-bot bypass)
- **`llm`**: LLM-generated content (domain inaccessible)

## Configuration

### Environment Variables Required

```env
OPENAI_API_KEY=sk-...       # For LLM context generation
JINA_API_KEY=jina-...       # Optional, for Jina Reader API
DATABASE_URL=postgres://... # Database connection
```

## Fallback Behavior

### LLM Context Fallback

If the LLM API call fails, the system falls back to a structured response built from:
- Domain name
- Provided location
- Provided keywords
- Provided phrases

This ensures domains are always created with some meaningful context.

## Examples

### Example 1: Accessible Domain
```bash
curl -X POST http://localhost:3000/api/domain-validation/validate-domain \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "google.com",
    "location": "San Francisco"
  }'
```
Result: `accessMethod: "http"`

### Example 2: JavaScript-Heavy Site
```bash
curl -X POST http://localhost:3000/api/domain-validation/validate-domain \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "app.example.com",
    "location": "Seattle"
  }'
```
Result: `accessMethod: "puppeteer"` (Puppeteer detects and renders JS)

### Example 3: Inaccessible Domain (LLM Generation)
```bash
curl -X POST http://localhost:3000/api/domain-validation/validate-domain \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "secretcorp.internal",
    "location": "Tokyo",
    "customKeywords": "corporate solutions, B2B services",
    "intentPhrases": "enterprise software, cloud services"
  }'
```
Result: `aiGenerated: true`, domain created with LLM-generated context

## Troubleshooting

### Domain Always Fails Accessibility Check

1. Check if domain is valid and resolvable
2. Check for network connectivity
3. Check if Puppeteer can launch:
   - Ensure Chrome/Chromium is available
   - Check `--no-sandbox` compatibility on your OS
4. Check Jina API key if using that fallback

### LLM Context Generation Fails

1. Verify `OPENAI_API_KEY` is set and valid
2. Check OpenAI API quota/billing
3. System falls back to basic context structure
4. Domain is still created in database

## Performance Notes

- HTTP check: ~1-3 seconds (fastest)
- Puppeteer check: ~6-8 seconds
- Jina Reader: ~3-5 seconds
- LLM generation: ~2-4 seconds

Total worst-case (all fallbacks): ~15-20 seconds
